# Visual inspection catalogue

Complete the mandatory [checklist](checklist.md); use this catalogue to interpret findings and choose corrections. These are prompts for observation, not bans or an AI detector. Prioritize demonstrated harm. No universal font, radius, word budget, image count or animation quota applies.

| Area / ID | Observe and diagnose | Useful correction | Keep / exception |
|---|---|---|---|
| Composition C1 | Repeated equal-size blocks give unequal information equal weight | Make the task/evidence lead; use rows, a table, grouped prose or an appropriate grid | Equally important comparable items benefit from equal treatment |
| C2 | Template hero/feature/CTA sequence hides the actual product or workflow | Start with what the audience needs to see or do; reorder existing content | Conventional sequence is useful when it fits the content |
| C3 | Container layers consume space without adding grouping | Group by alignment/spacing; remove redundant surfaces | Independent objects, embeds and previews can nest |
| C4 | The primary action competes with secondary actions or decorative content | Establish hierarchy through position, weight and grouping | Different independently actionable regions can each have an action |
| C5 | Abrupt section or page styles break a coherent system | Unify meaningful tokens and component roles | Deliberate campaigns/editorial sections may differ |
| Scale S1 | Oversized headings/controls or empty bands displace useful content | Size by role and viewport; rebalance the first screen | Spacious editorial and photographic compositions can be appropriate |
| S2 | One gap everywhere hides relationships; headings sit nearer unrelated groups | Tighten related content, separate groups, retain a small consistent scale | A regular list or table needs regular rhythm |
| S3 | Excessive density prevents scanning, or sparse widgets hide a work queue | Match density to repeated task and information priority | Experienced users may need compact controls and dense tables |
| S4 | Arbitrary padding, widths or alignment drift among equivalent components | Reuse project scale, align meaningful edges, allow optical corrections | Small optical differences need not be forced onto a grid |
| Typography T1 | Flat size/weight hierarchy or too many competing treatments | Give a few roles distinct emphasis | Data-heavy interfaces can have restrained scale |
| T2 | A familiar combination of family, scale, weights and labels substitutes for a product-specific choice; presence in source is mistaken for a brand requirement | Establish actual constraints; assess character and function together. For an unresolved choice in authorized redesign, compare real-content samples using [typography.md](typography.md) | Keep explicit brand requirements and demonstrated fit. Familiar families may win the comparison; neither novelty nor switching is a goal |
| T3 | Missing glyphs/fallbacks, Cyrillic mismatch, synthetic weights or unloaded font | Verify rendered family/glyphs; use available supported fonts | A fallback is fine if intentional and coherent |
| T4 | Long lines, tight leading, weak contrast or broken wrapping obstruct reading | Correct measure, leading, available width and actual contrast | Labels, code, numbers and long-form prose have different needs |
| T5 | Repeated uppercase kickers, italic/color single words or mono labels add no information | Keep useful labels; simplify redundant emphasis | Category/date labels, identifiers and a coherent editorial style can justify them |
| Color V1 | Default gradient/glow/palette repeats without supporting content or identity | Use product palette and purposeful emphasis | Brand gradients, expressive media and visualized values can be intentional |
| V2 | Replacing purple with cream/serif/terracotta or black/lime merely changes the template | Choose from the product and task; reconsider composition | Those palettes are valid when they fit the brief |
| V3 | Meaning depends on color alone or adjacent colors lack necessary contrast | Add labels/shapes; measure actual composited colors | Decorative colors need no semantic meaning |
| Surfaces V4 | Same radius on every layer causes awkward nesting or hierarchy | Choose radii by role; inspect inner/outer geometry | A coherent shared radius can work on peer components |
| V5 | Multiple borders, glass, shadows and tints compete or obscure text | Remove redundant separators; use restrained elevation | Overlays and deliberate material systems may need blur/shadow |
| V6 | Border clipping leaves broken rounded corners | Put clipping, radius and perimeter border on appropriate owning boxes | Intentional straight dividers need not wrap corners |
| Components K1 | Every feature has the same decorative icon tile or pill | Keep meaningful icons/status, simplify filler | Useful status tags and consistent iconography aid scanning |
| K2 | Repeated filters or metric cards obscure the control/data relationship | Group controls at the scope they affect; promote important data | Independent card scopes legitimately need independent controls |
| K3 | Mixed strokes, inconsistent control sizes or shifted baselines disrupt a shared layer | Align roles and icon metrics; reuse existing primitives | Brand/platform symbols can coexist with action icons |
| K4 | Labels wrap badly, values truncate without access or controls jump between states | Accommodate realistic text and stable bounds | Ellipsis with an accessible reveal or deliberate table scrolling can work |
| Assets A1 | Generic images or abstract decoration substitute for product-specific material | Use existing real assets or clear diagrams of supplied facts | Atmospheric/editorial visuals may be the intended subject |
| A2 | Missing, distorted, low-resolution or misleading media | Correct source, crop, aspect ratio and labeling | Clearly marked placeholders may remain when assets are unavailable |
| Copy A3 | Portable promises, repeated facts or vague actions obscure what happens | Use existing specific facts and precise action labels | Do not invent numbers, testimonials, customers or backend outcomes |
| Responsive R1 | Overflow, overlapping chrome, hidden deciding fields/actions or desktop shrink-to-fit | Reflow structure; expose task-critical fields and actions together through compact items or pinned columns | Comparison tables/code may need contained scrolling; a scrolling hint alone does not establish task usability |
| R2 | Long translations, zoom, narrow width or larger text break the layout | Test actual long content and preserve access | Do not shorten required labels/data merely to pass a screenshot |
| States I1 | Selected/disabled/loading/empty/error/success/permission states are missing or misleading | Exercise reachable states and show feedback/recovery at the right place | Unreachable states are not mandatory inventions |
| I2 | Hover lift/reveal animation repeats without explaining a change | Keep useful feedback, stable layout and reduced-motion behavior | Expressive motion can serve a campaign; static screenshots cannot judge it |
| I3 | Invisible focus, unlabeled controls, keyboard traps or unusable targets | Inspect semantics and test keyboard/touch as appropriate | Browser emulation is not proof of a physical-device test |

For every candidate ask: what was observed, what task does it obstruct, could it be deliberate, and will the proposed correction improve this screen without losing something useful? Mark unknown when available evidence cannot decide.
