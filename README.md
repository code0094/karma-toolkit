# Karma Toolkit

Одиннадцать навыков для разработки, диагностики, проверки интерфейсов и подготовки к выпуску. Работают как отдельные навыки Codex и как плагин Claude Code. Каждый навык решает конкретную задачу и сообщает, что удалось проверить, а что осталось неизвестным.

## Навыки

| Навык | Когда использовать |
|---|---|
| `karma-humanize` | Отредактировать русский или английский текст: убрать воду и шаблонные обороты, сохранить смысл и авторскую позицию. |
| `karma-slop` | Проверить интерфейс по 48 пунктам, оценить наполнение и типографику, показать исправленный адаптивный макет до/после. |
| `karma-debug` | Разобраться с конкретным сбоем, проверить гипотезы и по поручению исправить причину. |
| `karma-tests` | Проверить тесты, покрыть существующее поведение или реализовать изменение через TDD. |
| `karma-loop` | Улучшить выбранный участок кода через независимое ревью и проверку исправлений. |
| `karma-refactoring-ui` | Перенести визуальные стили внутрь компонентов, сохранив внешнюю композицию раскладки. |
| `karma-load` | Найти узкие места бэкенда локальной нагрузкой и измерить эффект исправлений. |
| `karma-security` | Провести аудит авторизованного кода и подтвердить найденные уязвимости. |
| `karma-logs` | Проверить, помогут ли логи и метрики разобраться со сбоем. |
| `karma-best-practices` | Сравнить готовые библиотеки, образцы реализации и собственное решение под конкретную задачу. |
| `karma-preflight` | Собрать результаты проверок релиза и полный список препятствий для выпуска. |

В Codex навык можно вызвать как `$karma-tests`, в Claude Code — как `/karma-toolkit:karma-tests`. Формулируйте нужный результат и границы задачи.

## Инспекция интерфейса: karma-slop

Навык осматривает отрисованный интерфейс, проходит 48 пунктов и различает дефекты, неуместные шаблоны и необязательные направления дизайна. Затем создаёт изолированный макет и проверяет его в браузере на широком и узком экранах. «Только аудит» не разрешает менять продукт; внедрение в рабочий код нужно указать отдельно.

Чек-лист охватывает композицию, плотность, размеры, типографику, цвет, декор, компоненты, изображения, тексты, состояния и доступ к действиям. Это не детектор AI-авторства и не список запрещённых шрифтов или градиентов. Уместное решение можно сохранить.

Перед существенным редизайном навык кратко фиксирует, для кого экран, какую задачу решает, что сохранить и что усилить. После правок проверяет, не потерялись ли характер и полезная плотность; обычные формы не обязаны быть уникальными. Основные исправления объясняет на статическом сравнении с фрагментами или отметками по делу — без видео, второго чек-листа и обязательного согласования очевидных решений.

Шрифт в исходнике не считается автоматически утверждённой частью бренда. При незаданном стиле и признаках шаблонной типографики навык сравнивает текущий вариант с двумя альтернативами на реальном фрагменте экрана. Проверяет не только семейство, но и иерархию, переносы, кириллицу и плотность. Исходный вариант может выиграть; вкусовое предпочтение не выдаётся за доказанное улучшение UX.

Полезные действия не удаляются ради чистого макета: если нет аудио или API, Play, сохранение и другие предусмотренные функции остаются с объяснением недоступности либо явно обозначенной локальной симуляцией. При разрешённой редактуре используется `karma-humanize`; если его нет, действует консервативная редактура с указанием ограничения.

Примеры:

- `$karma-slop Проверь этот лендинг и покажи исправленный макет. Сохрани тексты и все действия; рабочий сайт не меняй.`
- `$karma-slop Проверь CRM на шаблонное оформление. Сравни типографику на реальных строках и сохрани плотность таблицы.`
- `$karma-slop Только аудит этого экрана: все 48 пунктов, наблюдения и приоритеты. Без изменений файлов продукта.`

Результат — сравнение до/после, макет, заполненный чек-лист, существенные изменения и пределы проверки. Для предпросмотра в изолированном чате нужные изображения, стили, скрипты и шрифты упаковываются внутрь отчёта. Новый стиль сам по себе не считается улучшением.

## Редактура текста: karma-humanize

Навык работает с русским и английским текстом. Проверяет структуру, обоснованность утверждений, синтаксис, ритм и лексику; сохраняет факты, оговорки, цитаты и голос автора. Если текст уже хорош, может оставить его без изменений. Исходные редакторские правила и справочники сохранены; в Toolkit изменено имя навыка и добавлены метаданные интерфейса.

Примеры запросов в Codex:

- `$karma-humanize Убери нейросетевость из этого Telegram-поста. Сохрани цифры и мою позицию: …`
- `$karma-humanize Проверь этот README на канцелярит и шаблонные фразы. Пока не переписывай: …`
- `$karma-humanize Сделай письмо клиенту естественнее, сохрани срок, условия и деловой тон: …`
- `$karma-humanize Отредактируй английское описание PR. Не меняй термины, причины изменений и результаты проверок: …`
- `$karma-humanize Собери из этих заметок связный технический пост, не добавляй фактов: …`

Для Claude Code используйте `/karma-toolkit:karma-humanize`. Можно попросить только разбор или правку. По умолчанию ответ содержит отредактированный текст и краткие пояснения; для длинных материалов — таблицу изменений. Если утверждению не хватает опоры в исходнике, навык отмечает, что нужно уточнить у автора.

Это редактор текста, а не проверка его авторства и не гарантия обхода детекторов. Он не включён в стартовый хук или preflight. Оригинальная лицензия хранится в папке навыка; сведения об исходной версии — в `UPSTREAM.json`.

## Как начинается работа

При прямом запуске **karma-tests сначала спрашивает режим**:

1. **Аудит и план покрытия** — изучить существующие тесты, выполнить подходящие проверки и описать пробелы.
2. **Тесты для существующего поведения** — добавить тесты и необходимые фикстуры; найденные ошибки сообщить отдельно.
3. **Разработка через TDD** — написать тест, увидеть ожидаемое падение, реализовать изменение, получить успешный результат и выполнить рефакторинг.

Выбранный режим сохраняется на время задачи. Если он уже указан пользователем или передан из preflight, повторного вопроса нет. Выбор TDD разрешает менять и тесты, и рабочий код в рамках порученной задачи; подтверждение каждого шага не требуется.

Остальные навыки ориентируются на поручение: «проверь» означает аудит, «исправь» — реализацию с проверкой. Если отсутствует существенное решение или работа выходит за согласованные границы, агент задаёт уточняющий вопрос. Коммиты, отправка изменений и развёртывание не следуют автоматически из запуска навыка.

## Проектная память — AGENTS.md

Постоянные правила и принятые решения записываются в **AGENTS.md** соответствующего проекта или области. Навык обновляет только свой блок внутри `<!-- karma-toolkit:start -->`, сохраняет чужие инструкции и не создаёт дубликатов. Изменение проектной памяти входит в разрешённую реализацию; при запросе только аудита агент предлагает запись в отчёте.

Подробные сведения остаются в отдельных документах. Для тестов это существующий каталог проекта либо `notes/test-catalog.md`:

- сценарий и модуль;
- файлы тестов и команда запуска;
- непокрытые случаи;
- дата и контекст последней реальной проверки, её результат.

В AGENTS.md находится ссылка на каталог и краткое правило test-first для изменений поведения, где осмысленный автотест практичен. Каталог помогает найти тесты, но не доказывает, что текущая версия проходит проверки.

## Цикл качества

У `karma-loop` по умолчанию до **четырёх раундов исправлений**, затем итоговое ревью. Цель — устранить подтверждённые проблемы и пройти проверки. Повторение взаимно отменяющих правок или отсутствие прогресса приводит к остановке с отчётом.

Непрерывный режим включается явным запросом. Если нужен прежний критерий «9,5 на двух независимых проходах подряд», укажите его отдельно. Ограничения среды и заданный бюджет сохраняются; достигнутый лимит не считается успешным завершением.

## Нагрузка, безопасность и выпуск

- Нагрузочные тесты работают с изолированными тестовыми данными и ресурсами. Очистка затрагивает только ресурсы, созданные данным запуском. Локальные замеры не определяют производственную пропускную способность.
- Аудит безопасности различает подтверждённые находки и непроверенные гипотезы. Секреты скрываются в выводе. Доступ к коду не означает разрешения изменять работающую production-систему.
- Preflight продолжает независимые безопасные проверки после обнаружения проблемы. Обязательная проверка, которую не удалось выполнить, означает **NO-GO**, а не молчаливый пропуск.
- Диагностика и аудит не дают гарантии отсутствия ошибок; отчёт содержит фактические результаты и ограничения.

## Установка в Codex

Попросите встроенный `skill-installer` установить навыки из репозитория:

> Установи все одиннадцать навыков из code0094/karma-toolkit, каталог plugins/karma-toolkit/skills, через skill-installer.

Это установка отдельных навыков, а не регистрация Claude-плагина в Codex. Хук Claude при такой установке не используется. Навыки доступны на следующем ходе после обновления каталога навыков.

Для локальной разработки можно скопировать одиннадцать папок из `plugins/karma-toolkit/skills/` в `~/.codex/skills/`. Перед заменой сохраните существующие версии **вне** каталогов обнаружения навыков. Папка с названием `.local-copy-backup` внутри skills тоже может быть обнаружена как отдельный навык.

Установка через skill-installer создаёт локальную копию и сама по себе не включает автоматические обновления. Обновлять её следует явно из нужной версии репозитория, сохраняя локальные изменения.

## Установка в Claude Code

Выполните в Claude Code:

```text
/plugin marketplace add https://github.com/code0094/karma-toolkit
/plugin install karma-toolkit@karma
```

Обновление маркетплейса: `/plugin marketplace update karma`. Команды навыков имеют вид `/karma-toolkit:karma-debug`.

Хук SessionStart напоминает о границах поручения, выборе режима тестирования и AGENTS.md. Он не меняет файлы, не переключает режим приложения и не требует повторного разрешения на уже порученные действия.

## Локальная проверка

```bash
# Проверить состав, ссылки, 48 пунктов, лицензии и запуск хука без записи файлов:
node scripts/validate-toolkit.mjs

# Проверить JavaScript хука и формат его ответа:
node --check plugins/karma-toolkit/scripts/session-start.js
node plugins/karma-toolkit/scripts/session-start.js | python3 -m json.tool

# Загрузить локальный плагин в Claude Code:
claude --plugin-dir ./plugins/karma-toolkit

# Проверить упаковку средствами Claude Code:
claude plugin validate ./plugins/karma-toolkit
```

Для проверки описаний и структуры навыков используйте `quick_validate.py` из установленного `skill-creator`. Такая проверка не доказывает правильность поведения: отдельно проверьте выбор режима, границы задачи, обновление AGENTS.md и отчёт о невыполненных проверках.

## Структура

```text
.claude-plugin/marketplace.json       — описание маркетплейса Claude
plugins/karma-toolkit/
  .claude-plugin/plugin.json         — описание плагина
  hooks/hooks.json                  — регистрация SessionStart
  scripts/session-start.js          — контекст при старте сессии
  skills/karma-*/SKILL.md            — одиннадцать переносимых навыков
```
